# 그룹 초대 연결

1. Supabase SQL Editor에서 migrations/202609100001_group_invitations.sql 전체를 실행합니다.
2. tests/group_invitations.sql 전체를 새 쿼리에서 실행합니다. 임시 계정과 데이터는 ROLLBACK됩니다. 오류가 나면 ROLLBACK; 실행 후 오류를 확인하세요.
3. 발신·수신 계정의 모아 페이지를 모두 새로고침합니다.
4. 그룹 생성 시 이메일을 입력하거나, 기존 그룹의 구성원 관리에서 이메일을 입력하고 ‘초대 보내기’를 누릅니다.
5. 수신 계정의 상단 ‘받은 그룹 초대’에서 수락 또는 거절합니다.
6. 수락하면 그룹 캘린더가 나타납니다. 일정을 추가하고 상대 화면에서 ‘새로고침’을 눌러 확인합니다.

이메일을 보내는 기능이 아닌 모아 내부 알림입니다. 기존의 미발송 목록은 자동 발송하지 않습니다. 기존 그룹에서 같은 주소를 다시 입력해 초대해주세요.
수신자는 회원가입과 이메일 인증을 완료한 계정이어야 합니다. 그룹장만 초대·초대 취소·그룹 정보 변경·삭제를 할 수 있고, 수락한 구성원은 그룹 일정을 읽고 추가·수정·삭제할 수 있습니다.

첫 초대 시 기존 개인 그룹과 그 그룹의 일정만 공유 테이블로 옮겨 사용합니다. 개인·취미 일정은 공유하지 않습니다. 생성한 공유 그룹이 없는 동안에는 기존 저장 방식을 사용합니다.
사진·추억 기록은 아직 브라우저 전용이며 공유하지 않습니다. 자동 갱신은 화면이 보이고 편집 대화상자가 닫혀 있을 때 15초 간격으로 작동합니다.

관리 위치:
- moa_shared_groups: 그룹 정보와 그룹 일정, owner_id는 그룹장
- moa_group_members: 초대를 수락한 구성원
- moa_group_invites: pending(대기), accepted(수락), declined(거절), cancelled(취소)

세 테이블은 RLS를 켜고 일반 클라이언트 직접 접근 권한을 제거했습니다. moa_groups 서버 함수가 인증된 계정과 그룹 권한을 검사합니다. 클라이언트가 다른 계정 ID를 보내는 방식으로 권한을 얻을 수 없습니다.
그룹장 계정 탈퇴 시 소유 그룹·초대·구성원·그룹 일정도 삭제됩니다. 구성원 탈퇴는 해당 구성원의 참여·초대 정보만 삭제합니다.

검증:
- 로컬 JavaScript 검사와 저장/알림 테스트를 실행했습니다.
- 실제 Supabase의 SQL 실행과 두 계정 송수신은 사용자 프로젝트에서 확인해야 합니다. 테스트 SQL은 외부인 접근 차단, 수락 전 접근 차단, 거절/재초대/수락, 공동 일정 변경과 충돌, 그룹장 권한 및 탈퇴 시 정리를 검사합니다.
