# 취미 통합 · 주간 시간표 안내

## 적용 순서

1. 변경된 프로젝트 파일을 사용하고, 이전에 열어 둔 모아 탭은 새로고침해 주세요.
2. 기존에 계정 일정 저장이 정상 작동했다면 **추가 SQL이나 SMTP 설정은 필요하지 않습니다.**
3. 메뉴의 **시간표**에서 빈 시간 칸을 선택해 저장합니다. ‘계정에 저장됐어요.’를 확인한 뒤 새로고침하면 다시 불러옵니다.
4. 모바일 하단 핸들 → **이번 주, 나를 위한 시간**에서 취미를 추가·수정하고 요일별 기록을 남깁니다. PC에서는 모아보기 오른쪽의 같은 패널을 사용합니다.

저장 설정이 전혀 없는 새 Supabase 프로젝트만 기존 migrations/202609080001_calendar_accounts.sql을 먼저 적용해야 합니다. 이미 적용한 프로젝트에서는 다시 실행하지 않아도 됩니다.

## 데이터와 공개 범위

- 기존 calendar_accounts.data에 habits(이름·목표), timetable(반복 블록·표시 설정)을 추가했습니다.
- 기록은 기존 checks의 동일한 취미 ID와 날짜를 계속 사용합니다. 독서·산책을 복제하거나 기록을 초기화하지 않습니다.
- 기존 events 중 취미 일정도 삭제하지 않습니다. 취미 탭의 ‘취미 캘린더 일정’에서 기존 입력 창으로 추가·수정·삭제할 수 있습니다.
- 목표는 주당 활동한 날 수(1~7일)이고 하루 한 번 기록합니다. 취미 삭제는 해당 취미와 그 기록을 삭제합니다.
- 시간표는 매주 반복되는 별도의 계획입니다. 개인·그룹 캘린더에 일정을 생성하지 않습니다.
- 기존 RLS가 계정 문서를 본인만 조회·수정하도록 제한합니다. 친구 캘린더 RPC는 공개된 events만 반환하므로 habits, checks, timetable을 반환하지 않습니다.
- 저장은 기존 버전 확인과 순차 저장을 재사용합니다. 저장 오류 때는 다시 저장할 수 있고, 다른 탭과 충돌하면 새로고침 안내가 표시됩니다.

## 시간표 사용

- 월~일을 항상 표시합니다. 표시 시작은 ‘적용’으로 저장하며, 종료는 24:00입니다.
- 30분 칸을 클릭/터치하거나 PC에서 같은 요일의 빈 칸을 드래그합니다. 입력 창에서 분 단위로 수정할 수 있습니다.
- 종료 시각은 시작보다 늦어야 합니다. 자정까지 이어지면 ‘자정(24:00)에 종료’를 선택하세요. 자정을 넘는 일정은 두 요일로 나눠 등록하세요.
- 겹치는 일정은 확인 항목을 선택한 뒤 저장하면 같은 열 안에 나란히 보입니다.
- 숨겨진 요일이나 표시 시간 밖의 일정은 ‘표시 범위 밖의 일정’에서 확인·수정할 수 있습니다.
- 모바일은 월~일 7개 열이 화면 너비 안에 들어오며 시간표 안에서 세로로 스크롤합니다. 작은 블록은 눌러 전체 내용을 확인합니다.

## 확인한 내용과 남은 기기 검증

- 자동 테스트: 분 단위 시각, 잘못된 종료 시각, 겹침·인접 시간, 겹친 블록 배치, 기존 기록 유지, 계정 문서 재조회와 충돌 처리.
- 브라우저에서 실제 로그인 계정으로 시간표 저장·새로고침 재조회·수정·삭제, PC 드래그, 모바일 크기의 칸 선택과 내부 스크롤을 확인했습니다.
- 취미 추가·기록·주간 목표 수정 후 새로고침해도 기록과 목표가 유지되는 것을 확인했습니다.
- 검증용으로 만든 일정·취미는 테스트 후 정리합니다.
- 실제 휴대폰의 터치 동작 및 로그아웃 후 다시 로그인하는 절차는 별도 확인이 필요합니다.
- 두 계정 사이의 실제 RLS 접근 검증은 이 환경에서 직접 실행하지 않았습니다. 필요하면 tests/personal-tools.sql 전체를 SQL Editor에 붙여 넣고 Run으로 검증할 수 있습니다. 기존 친구 SQL이 적용돼 있어야 하며, 임시 사용자·데이터는 마지막 rollback으로 모두 되돌립니다. 중간 오류가 나면 rollback;을 실행하세요.
